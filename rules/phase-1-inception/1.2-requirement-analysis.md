# Stage 1.2 — Requirement Analysis

**Goal:** find requirement defects **before** they become code or test defects.
**Agent:** `requirement-analyst`. **Output:** `1-inception/requirement-analysis.md`,
questions, DCPs.
**Light tier:** ambiguity scan only (step 2).

## Context slices
overview, glossary, features, rules, entities, roles, discrepancies, pendingDcps

## Steps — analyse every REQ against these lenses

| # | Lens | Look for | Finding type |
|---|---|---|---|
| 1 | Completeness | Missing actors, preconditions, error/empty states, limits, defaults | `missing` |
| 2 | Ambiguity | Vague words: *fast, easy, appropriate, etc., some, should, normally, user-friendly*; undefined terms not in glossary | `ambiguous` |
| 3 | Consistency | Contradictions within the item, or with confirmed domain rules / other open items | `conflict` |
| 4 | Testability | Can an observer decide pass/fail? Is the expected result observable? | `untestable` |
| 5 | Domain alignment | Uses terms differently from glossary; violates/changes a BR; new rule introduced | `domain-change` |
| 6 | Roles & permissions | Who can/can't do it; behaviour for each relevant role | `missing` |
| 7 | Data & states | Entity state transitions introduced/changed; data lifecycle; migration of existing data | `missing` |
| 8 | Non-functional | Hidden NFRs: performance, security, privacy/PII, accessibility, audit, localisation, concurrency | `nfr` |
| 9 | Dependencies | Integrations, feature flags, other teams, config | `dependency` |
| 10 | Feasibility to test | Environments, data, third-party sandboxes available? | `test-constraint` |

## Steps
1. Apply lenses; record each finding `RA-01..` with REQ reference, type, severity
   (`blocking`/`major`/`minor`), evidence and proposed resolution.
2. Every `blocking`/`major` finding that needs a human → question (question-protocol).
3. `domain-change` findings → raise DCPs (new terms, new/changed rules); cite REQ.
4. Compute a **requirement quality score**: % REQs with no major/blocking finding.

## Self-check
- [ ] All 10 lenses applied to every REQ (record "no finding" explicitly in the lens matrix)
- [ ] Each blocking finding has a question
- [ ] DCPs raised for domain changes, listed in the artifact
