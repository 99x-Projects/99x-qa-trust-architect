# Stage 1.5 — Gap Analysis

**Goal:** make every known gap explicit so it is planned, closed, or consciously accepted.
**Agent:** `risk-gap-analyst`. **Output:** `1-inception/gap-analysis.md`.

## Gap types

| Type | Question | Inputs |
|---|---|---|
| **Requirement gap** | What is still undefined after G1? | requirement-analysis open findings, provisional AC |
| **Coverage gap** | Which AC/risks/impacted areas have no existing test? | AC, risk-assessment, feature-test-map |
| **Automation gap** | Which existing manual-only areas are high-risk and repetitive? | feature-test-map (manual vs automated), hotspots |
| **NFR gap** | Which NFR targets apply but have no test approach? | quality-standards NFR, requirement-analysis `nfr` findings |
| **Environment / data gap** | What environment, data, sandbox, or access is missing? | environments.yaml, integrations.yaml, `test-constraint` findings |
| **Domain gap** | Which facts needed are skeleton/provisional/disputed? | context loader statuses, discrepancies |
| **Observability gap** | Can we see in production whether this works? | integrations, existing monitoring (qa-profile) |

## Steps
1. For each type, list `GAP-01..` with: description, evidence, severity (high/medium/low),
   linked AC/R/F IDs, proposed closure (new TC, automation backlog item, env request,
   question, DCP, monitoring item, or accept), owner (role).
2. **Coverage matrix:** AC × {existing test, planned new test, none}.
3. Summarise counts per type and severity at the top.

## Self-check
- [ ] Every high risk with no existing coverage appears as a coverage gap
- [ ] Every gap has a proposed closure or an explicit "accept" with reason
