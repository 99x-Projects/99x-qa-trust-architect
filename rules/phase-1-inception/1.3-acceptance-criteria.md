# Stage 1.3 — Acceptance Criteria

**Goal:** a complete, testable, agreed set of acceptance criteria.
**Agent:** `requirement-analyst`. **Output:** `1-inception/acceptance-criteria.md`.
**Light tier:** validate and minimally fix existing AC only.

## Formats (both allowed — choose per criterion)

**Gherkin** — best for behaviour/flows:
```gherkin
AC-03  Reject leave over the limit           [REQ-02] [BR-012] [ROLE-employee]
  Given an employee with 25 days of leave balance
  When they request 21 consecutive days
  Then the request is rejected
  And the message "Leave cannot exceed 20 days per request" is shown
```

**Rule table** — best for calculations, combinations, validation matrices:
```
AC-05  Approval routing                       [REQ-03] [BR-020]
| Requester role | Days   | Approver        |
|----------------|--------|-----------------|
| employee       | ≤ 5    | line manager    |
| employee       | > 5    | line manager+HR |
| manager        | any    | department head |
```

Choose: Gherkin for sequences/interactions; rule table when ≥ 3 input combinations or
a calculation. Record `format` per AC.

## Steps
1. Start from existing AC (1.1) and resolved analysis findings (1.2).
2. For each REQ write AC covering: happy path, **negative paths**, **boundaries**,
   permission variants, state preconditions, error messages/feedback, relevant NFR.
3. Tag each AC with REQ, BR, ROLE, ENT/state IDs (traceability).
4. Quality check every AC:
   - **Atomic** (one behaviour) · **Observable** outcome · **Unambiguous** values
   - **Independent** of implementation (no "click the blue button")
   - Uses glossary terms
5. Mark each AC `basis: confirmed | provisional (DCP-xxxx / BR-xxx observed)`.
6. Coverage table REQ → AC. Every REQ must have ≥ 1 AC.

## On G1 approval → sync
If `acceptanceCriteria.pushToPlatform`: adapter `updateAcceptanceCriteria` writes the
approved AC (rendered Markdown/HTML) to the work item's AC field.

## Self-check
- [ ] Every REQ has ≥ 1 AC, and ≥ 1 negative AC where input exists
- [ ] Boundaries stated with exact values for every limit
- [ ] Every AC passes the quality checks
- [ ] Provisional AC are tagged
