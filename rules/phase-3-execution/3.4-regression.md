# Stage 3.4 — Regression

**Goal:** show that the change did not break what already worked, using existing automated tests
first and manual regression TCs where nothing automated exists.
**Agent:** `execution-analyst` (selection, import, triage); orchestrator for manual runs.
**Output:** `ITEM_DIR/3-execution/regression.md` (template `templates/regression.md`), runs with
`set: regression`.

## Context slices
features, existingTests, hotspots, integrations

## Inputs
- `1-inception/risk-assessment.md` → impacted features (scope + adjacent) and regression candidates
- `_project/feature-test-map.yaml`
- Approved TCs of **earlier** work items for the same features (`QA_ROOT/*/2-design/test-cases/`)
  with `priority: 1` — candidate manual regression
- Light tier: impacted feature only; standard: scope + adjacent; comprehensive: + two hops and
  hotspots

## Steps

### 1. Select
1. Start from the risk assessment candidates.
2. Add tests mapped in `feature-test-map.yaml` to impacted features that are not already listed.
3. Add P1 TCs from earlier items for impacted features that have **no** automated coverage.
4. Record per test: type, feature, reason, source. List impacted areas with no regression test →
   reference/raise a GAP in `gap-analysis.md` (append, do not rewrite).

### 2. Say how to run it
For each automated group give the exact command or pipeline (from `qa-profile.yaml` test frameworks
and CI), with a reporter that produces JUnit XML or TRX, e.g.
`dotnet test --filter "Category=Leave" --logger trx`, `npx playwright test leave --reporter=junit`,
`pytest -k leave --junitxml=test-results/junit.xml`.
Running tests locally is **the tester's choice**: offer to run the command via Bash only if the tester
agrees and the command targets a non-production environment; otherwise ask for the result file
(or the CI artifact) path.

### 3. Import automated results
Run the importer (stdlib):
```
python <FRAMEWORK_ROOT>/scripts/import_results.py <file-or-glob>... [--format junit|trx]
```
It prints normalised JSON: one entry per test with `name`, `classname`, `result`,
`durationMs`, `message`, `tcIds` (TC-xxx ids found in names/categories/properties).
Create one `RUN-xxx.yaml` per test **in the regression selection** (and per TC whose id appears in
`tcIds`), `mode: automated`, `set: regression` (or `planned` for TC ids of this item),
`source: <file>`. Tests outside the selection are summarised in counts only — don't create runs.

### 4. Manual regression
Execute manual regression TCs via 3.2a (`/qa-execute <id> --set regression`).

### 5. Triage failures
Apply 3.3 §1 classes. Flaky: re-run up to `execution.flakyReruns` times (ask the tester to re-run
or provide the re-run result file); pass on re-run → `flaky` (note it; recurring flakiness → automation
backlog item), consistent failure → triage further. Product defects → 3.3 draft.
