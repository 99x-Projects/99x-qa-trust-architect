## Design (agreed)
- **Session types:** focused (impact areas from 1.4 + gaps from 1.5), charter-based
  exploratory (charters from risks), bug re-verification.
- **Modes:** autonomous (AI explores within charter/time-box), guided (tester steers in chat),
  pair (tester drives headed browser; AI observes snapshots and takes notes).
- **Context:** context-loader slices appmap, journeys, roles, rules (oracle), quirks, environments.
  Charters cite rules, journeys, pages and quirks explicitly.
- **Loop:** snapshot (accessibility tree) → choose action via heuristics (boundaries, invalid
  input, interruptions, back/refresh, permissions, i18n, a11y) → act → observe UI + console
  errors + failed network calls → log step + evidence.
- **Outputs:** `3-execution/sessions/<date>-<charter>/{charter.md, session-report.md, evidence/}`;
  confirmed bugs → adapter createDefect (**always tester-confirmed**); new TCs → 2.1;
  automation candidates → 2.3; new pages → app-map DCP (auto level); rule conflicts →
  discrepancies + DCP; provisional-only violations → questions, not defects.
- **Safety:** `exploratory.environments.allowed`, credentials only from env / storageState,
  `guards.blockActions` need confirmation, `maxSessionMinutes`.
- **Live crawl** for 0.2 domain discovery reuses the same MCP setup (per role → app-map).
