# Stage 3.3 — Defect Management

**Goal:** turn real failures into well-formed, traceable defects — and keep non-defects out of
the tracker.
**Agent:** `execution-analyst` (triage, drafting, checks); orchestrator (`/qa-defect`) for
confirmation; `sync-agent` for platform writes.
**Output:** `ITEM_DIR/3-execution/defects/DEF-xxx.yaml` (template `templates/defect.yaml`,
schema `schemas/defect.schema.json`), `defect-log.md`; platform defects after confirmation.

> **Hard rule:** a defect is created on the platform **only after a named tester confirms it**.
> No exceptions, including bulk operations ("confirm all" must list the defects first).

## Context slices
rules, quirks, roles, features, discrepancies, pendingDcps

## 1. Triage each failed / blocked run

Set `failureClass` on the run:

| Class | Meaning | Next |
|---|---|---|
| `product-defect` | The application behaves wrongly against an eligible oracle | Draft DEF |
| `test-defect` | The TC is wrong/outdated (expected result, steps, data) | Fix TC → `needs-review` at G3 scope; re-run |
| `environment` | Env down, misconfigured, dependency unavailable | Note; re-run when fixed; recurring → testing risk |
| `data` | Test data missing/wrong state | Fix data (2.2); re-run |
| `flaky` | Non-deterministic (automated) | Re-run per `execution.flakyReruns`; track |
| `expected-quirk` | Matches `known-quirks.md` | No defect; reference the quirk |
| `provisional-oracle` | Expected result rests only on a provisional/observed/inferred/disputed fact | **No defect** → question (+ discrepancy/DCP) |

Ask the tester when the class is not clear from the evidence.

## 2. Oracle check (before drafting)

The expected result must come from an oracle-eligible source (`core/context-loader.md` §4):
- an approved AC (G1 approved/with-risks) → `oracleBasis: acceptance-criterion`
- a `confirmed` business rule → `confirmed`
- a `documented` rule with `verified: true` → `documented-verified`

If the TC has `basis: provisional`, or the only source is an observed/inferred/disputed fact or
a pending DCP, and `domain.provisionalFacts.canFailTests: false` → class `provisional-oracle`:
write a question in `questions.md` ("Observed X, expected Y per BR-020 (observed). Which is
correct?"), add/extend a discrepancy, and list it under "Not raised as defects" in `defect-log.md`.

## 3. Draft the defect

1. **Title:** `<what is wrong> — <where>`, ≤ 120 chars, no "Test failed" titles.
2. **Steps to reproduce:** from the TC steps + data actually used + role reference + environment;
   minimal and numbered.
3. **Expected** (cite AC/BR ids) vs **actual** (from the run).
4. **Severity** per `quality-standards.md` scale; **priority** suggestion (P1 when it blocks a
   journey or a P1 TC). Severity is a suggestion — the tester decides at confirmation.
5. **Traces:** work item, runs, TCs, AC, rules, features (+ session for exploratory).
6. **Evidence:** run evidence paths.
7. **Checks:**
   - `knownQuirk`: search `known-quirks.md` — a match means re-class as `expected-quirk` unless the tester disagrees.
   - `possibleDuplicates`: if `execution.defects.duplicateCheck` and the platform is enabled, query open
     defects linked to the work item or with the same feature tag / similar title (adapter
     `queryWorkItems`); also other `DEF-*.yaml` in the repo for the same item.
   - `reproduced`: if `requireReproduction: true`, ask the tester to reproduce once before confirming.
8. `status: draft`. Record `DEFECT-DRAFTED DEF-xxx from RUN-xxx` in `audit.md`.

## 4. Confirm (human) — `/qa-defect confirm`

Show each draft compactly (title, severity, expected/actual, oracle, duplicates). The tester may
edit, then for each: **confirm** / **reject** (not a defect, reason) / **duplicate of <id>** / **defer**.
On confirm: `status: confirmed`, `confirmedBy`, `confirmedAt` → `DEFECT-CONFIRMED`.

## 5. Log on the platform (sync-agent, adapter `createDefect`)

Only when `storage.platform.enabled`. Dry run first (first write in the session), then create:
type `platform.<target>.defectType`, repro steps, severity/priority, system info (env/build), tags
(`qa-trust`, `qa-def:<workItemKey>/<DEF-id>`, feature ids), links (related → work item, tested-by →
platform test case), evidence attachments (`attachEvidence`). Idempotent: existing
`externalIds.<platform>` or a platform item carrying the same `qa-def:` tag → no new item.
Write the ID back; `status: logged` → `DEFECT-LOGGED`.

Platform disabled → keep `confirmed`; the defect lives in the repo only.

## 6. Follow the lifecycle

- **Refresh** (`/qa-defect refresh`, and `/qa-status` when `refreshStatusOnStatus`): read platform
  state → `platformState`; map resolved/done states to `fixed`.
- **Retest** (`/qa-defect retest DEF-xxx`): execute the linked TC(s) (3.2a, `set: retest`,
  `retestOf: DEF-xxx`). Pass → `retest-passed` (offer to close on the platform via comment/state);
  fail → `retest-failed` (offer to re-activate with a comment). Record `RETEST`.
- **Accept / defer**: only with a named risk and who accepted it → feeds G4 C3 and the summary report.

## 7. Domain feedback

- ≥ 2 confirmed defects in the same feature in this item, or any Sev1 → DCP for
  `risk-hotspots.md` (review level).
- A defect revealing that a documented/confirmed rule is wrong in the *documentation* (not the code)
  → discrepancy + DCP.
