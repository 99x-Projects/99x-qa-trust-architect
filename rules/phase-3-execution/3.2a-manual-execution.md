# Stage 3.2a — Manual Execution

**Goal:** execute the planned test cases against a known build and environment, with
evidence, and record one result per execution.
**Who:** the orchestrator (`/qa-execute`, main session — a human executes); the
`execution-analyst` prepares the cycle and processes results.
**Output:** `ITEM_DIR/3-execution/runs/RUN-xxx.yaml` (template `templates/test-run.yaml`,
schema `schemas/test-run.schema.json`), `execution-log.md`, evidence under
`execution.evidencePath`, optional `execution-sheet-CY-xx.md`.

## Context slices
environments, roles, quirks, rules (oracle status only)

## Inputs
- `2-design/test-cases/*.yaml` with `status: approved` (G3 approved/overridden), `test-case-index.md`
- `1-inception/test-plan.md` §4 environments, §6 entry criteria (light tier: quality-standards defaults)
- `2-design/test-data.md`
- Tester's statement of **build** and **environment**

## Steps

### 1. Open a cycle (`CY-xx`)
1. Ask for the build/version (suggest the latest commit or the pipeline run if detectable) and the
   environment (default `execution.defaultEnvironment`). The environment must exist in
   `environments.yaml`; production is refused unless the environment entry explicitly allows it.
2. Check **entry criteria** (test-plan §6). Record each as met/unmet in `execution-log.md`.
   Unmet → advisory: tell the tester, ask to proceed; record `met-with-risks` and the reason.
3. Build the **execution list**: approved TCs with `level: manual`, or `automation.status` other than
   `automated`/`already-automated`, ordered by priority then risk, plus the observability
   verification checks `OBS-xx` from `2-design/observability-plan.md` (recorded with `testRef: OBS-xx`). Automated TCs are executed by the
   pipeline and imported (3.4 §3). Exclude TCs already passed in this cycle.
4. Assign testers if more than one (optional `assignee` column).

### 2. Execute — two modes (`execution.manualMode`, or ask)

**Interactive (in chat).** For one TC at a time:
1. Show the objective, preconditions, data set (and Examples row), and the steps with expected results
   (rule-table/Gherkin rendered as numbered steps — same conversion as the adapter).
2. Account to use: the **role reference** from `environments.yaml` (e.g. "use the account in
   `TEST_EMPLOYEE_USER`") — never read or display credential values.
3. Tester reports per step: `pass`, `fail <what happened>`, `blocked <why>`, or `skip`. Accept
   shorthand ("all pass", "step 3 fail: saved without warning").
4. On fail/blocked ask for evidence: a file path, or "none". Copy referenced files into
   `<evidencePath>/<RUN-id>/` (keep originals untouched).
5. Write `RUN-xxx.yaml` immediately after each TC (don't batch — sessions get interrupted).

**Sheet (offline).** Generate `3-execution/execution-sheet-CY-xx.md` from
`templates/execution-sheet.md` for the execution list. The tester fills it in and runs
`/qa-execute <id> --ingest`; then parse each TC block into a `RUN-xxx.yaml`. Ambiguous entries
(empty result, failed without note) → ask, don't guess.

### 3. Recording rules
- One run per TC execution (per Examples row when rows are executed separately and differ in result).
- `failed` needs `actual` (+ the failing `stepResults`); `blocked` needs `blockedReason`.
- `failureClass: untriaged` for every failed/blocked run — triage happens in 3.3.
- Never overwrite a run. Re-execution = new run (`set: retest` when it re-tests a defect fix).
- Append `RUN-RECORDED RUN-xxx TC-xxx <result>` to `audit.md`.

### 4. After each TC / session
- Failed run and `execution.defects.autoDraft: true` → hand to 3.3 (draft a defect). Ask the tester
  whether to draft now or at the end of the session.
- Regenerate `execution-log.md` (latest result per TC, totals, run history).
- `execution.publishRuns: after-session` → offer `/qa-sync --what runs`.

## Self-check
- [ ] Every run has build, environment, tester, timestamp
- [ ] Every failed/blocked run has actual/blocked reason and evidence or "none" recorded
- [ ] No credential values in any file
- [ ] `execution-log.md` totals match `runs/*.yaml`
