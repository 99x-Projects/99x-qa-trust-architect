# Stage 2.3 — Automation Gap Identification  *(MVP: draft quality)*

**Agent:** `automation-analyst`. **Output:** `2-design/automation-gap.md`.

## Steps
1. **Classify every TC**: `automate-unit` · `automate-api` · `automate-ui` ·
   `automate-contract` · `manual-only` · `exploratory` · `already-automated`.
   Prefer the **lowest level** that can observe the expected result (test pyramid).
2. **Score candidates** (1–5 each), Automation Value = (F + R + S + D) − E:
   - F Frequency of execution (regression relevance)
   - R Risk of the covered area
   - S Stability of the feature/UI (stable = higher)
   - D Determinism of expected result / data control
   - E Effort to automate (incl. framework gaps)
   Recommend: ≥ 12 automate now · 8–11 backlog · < 8 keep manual.
3. **Existing automation mapping**: match `already-automated` to concrete test paths.
4. **Framework gaps**: missing capabilities (no API test project, no UI framework, no test
   data builders) → list as `GAP-xx` (automation type).
5. **Automation backlog**: items to create on the platform (on G3, if user agrees) —
   adapter `createWorkItem(type: Task|Story, tag: qa-automation)`.
