# Stage 0.4 — Quality Standards

**Goal:** agree the project-wide quality rules every work item is measured against.
**Output:** `PROJECT_DIR/quality-standards.md` (template `templates/quality-standards.md`).

## Steps
1. Propose defaults from the template; adapt to detected stack and existing conventions
   (e.g. existing severity field values in the tracker via adapter `getFieldValues`).
2. Sections to agree:
   - **Definition of Ready for test design** (what G1 requires)
   - **Definition of Done for testing** (what G4 requires)
   - **Severity & priority scales** (mapped to platform values)
   - **Default entry & exit criteria** (quantified, e.g. "0 open Sev1/Sev2; ≥ 95% planned cases executed")
   - **NFR targets**: performance (p95 latency, throughput), accessibility (WCAG level),
     security baseline (OWASP ASVS level / top 10), browser/device matrix, localisation
   - **Test levels policy** (what belongs at unit / API / UI; target automation ratio)
   - **Evidence standards** (what proof a manual pass/fail needs)
3. Ask only for values that cannot be defaulted sensibly; mark defaults as `default` so
   they are visible at G0.

## Self-check
- [ ] Exit criteria are measurable
- [ ] Severity values map to the platform's field values
- [ ] NFR targets present or explicitly "not applicable"
