# Stage 0.1 — Workspace Detection

**Goal:** understand the project under test well enough to configure the framework.
**Runs:** on `/qa-init`, and on `/qa-domain refresh --profile`.
**Output:** `PROJECT_DIR/qa-profile.yaml` (template `templates/qa-profile.yaml`),
initial `qa-trust.config.yaml` (from `config/qa-trust.config.example.yaml`) if absent.

## Inputs
- Repository files (read-only)
- User answers to a short setup questionnaire

## Steps
1. **Project type.** Greenfield if there is little/no application source code and no
   tests; otherwise brownfield. Record evidence (file counts, first commit date if git).
2. **Tech stack.** Detect languages, frameworks, build tools from manifests
   (`package.json`, `*.csproj`/`*.sln`, `pom.xml`, `build.gradle`, `pyproject.toml`,
   `requirements.txt`, `go.mod`, `Gemfile`, ...).
3. **Test assets.** Detect test frameworks and folders (xUnit/NUnit/MSTest, Jest/Vitest,
   Playwright/Cypress/Selenium, pytest, JUnit, SpecFlow/Reqnroll/Cucumber `.feature` files,
   k6/JMeter, Postman collections). Count tests roughly per type.
4. **CI/CD.** `.github/workflows/`, `azure-pipelines.yml`, `.gitlab-ci.yml`, `Jenkinsfile`.
   Note which pipelines run tests.
5. **API & data contracts.** OpenAPI/Swagger, GraphQL schemas, DB migrations, ORM models.
6. **Documentation.** Requirement/spec folders, ADRs, wikis referenced in README,
   user manuals. Estimate documentation coverage (none / partial / good) per top-level area.
7. **Work item platform.** Infer from git remote (`dev.azure.com`/`visualstudio.com` →
   azure-devops; `github.com` → github) and README badges; Jira from links/keys like `ABC-123`.
   Confirm with the user.
8. **Environments.** Look for env config (`appsettings.*.json`, `.env.example`,
   deployment manifests) to list environment names/URLs. Never copy secrets.
9. **Other SDLC workflows.** Apply detection rules from each `integrations/*/integration.md`
   (e.g. AI-DLC: `aidlc-docs/` + `aidlc-state.md`). Record `detected`, `layoutVersion`, suggested mode.
10. **Observability stack** (for 2.4): App Insights, OpenTelemetry, Datadog, Grafana,
    Prometheus, ELK, Sentry — from dependencies/config.

11. **Secrets file.** Check `secrets.envFile` (default `.env`):
    - If missing, offer to create it from the plugin's `config/.env.example` (empty values;
      the user fills them in — never ask the user to paste a token into the chat).
    - Verify it is gitignored (`git check-ignore <file>`). If not, offer to add it to `.gitignore`.
    - Never read secret values into artifacts or output; only check whether required keys are set.

## Setup questionnaire (write to `PROJECT_DIR/questions.md`)
Ask only what detection could not settle, e.g.:
- Confirm work item platform + org/project (+ Test Plan ID for ADO)
- Where should QA artifacts live? (default `docs/qa`)
- Who are the testers (or "anyone")?
- Which environments may agents use? Which must they never touch?
- AI-DLC detected → companion mode OK?
