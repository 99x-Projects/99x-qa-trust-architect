# Stage 0.3 — QA Reverse Engineering (brownfield only)

**Goal:** inventory the existing QA assets so later gap analysis and automation analysis
start from reality, not from zero.
**Skip when:** `project.type: greenfield` (record `skipped: greenfield`).
**Output:** `PROJECT_DIR/qa-baseline.md` (template `templates/qa-baseline.md`),
`PROJECT_DIR/feature-test-map.yaml`.

## Steps
1. **Automated suites.** For each detected framework: location, test count, level
   (unit / integration / API / UI-E2E / contract / performance), how/where it runs in CI.
2. **Map tests → features.** Use test names, namespaces, folder structure, tested routes/APIs
   and `feature-map.yaml` keywords. Unmapped tests → list separately.
3. **Coverage signals.** Use existing coverage reports if present (`coverage.cobertura.xml`,
   `lcov.info`, `jacoco.xml`); do not run builds unless the user agrees.
4. **Flakiness & health.** From CI history if accessible (retries, quarantined tests,
   `[Ignore]`/`skip`/`xit` markers), and test files not modified for a long time vs.
   heavily changed source.
5. **Manual assets.** Existing test plans/cases on the platform (adapter `listTestCases`
   if supported), spreadsheets/docs referenced by the user, regression checklists.
6. **Defect hotspots.** Tracker bugs grouped by feature/area over `trackerHistory.lookbackMonths`
   → feed `risk-hotspots.md` via DCP-level facts (initial build: direct, approved at G0).

## feature-test-map.yaml shape
```yaml
features:
  F-leave-request:
    automated:
      unit: { count: 34, paths: ["tests/Leave.UnitTests/**"] }
      api:  { count: 6,  paths: ["tests/Api/LeaveApiTests.cs"] }
      ui:   { count: 2,  paths: ["e2e/leave.spec.ts"] }
    manual: { count: 12, source: "ADO Test Plan 88 / Suite 'Leave'" }
    flaky: ["e2e/leave.spec.ts > submits overlapping leave"]
    defects12m: 9
unmapped: ["tests/Misc/HelperTests.cs"]
```
