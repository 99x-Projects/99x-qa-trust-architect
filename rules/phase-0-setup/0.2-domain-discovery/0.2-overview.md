# Stage 0.2 — Domain Discovery (overview)

**Goal:** build the shared **domain context** about the application under test so every
agent has a reliable understanding of features, rules, roles, journeys and data.
**Agent:** `domain-analyst`.
**Output:** files under `DOMAIN_DIR` (templates in `templates/domain/`), project
`questions.md`, `discrepancies.md`.
**Approved at:** G0 (initial build). Afterwards all changes flow through DCPs.

## 1. Domain context parts

| File | Contents |
|---|---|
| `domain-overview.md` | 1-page summary + `domainVersion` front-matter |
| `glossary.md` | Terms, synonyms, abbreviations |
| `personas-roles.yaml` | Roles, permissions, typical goals |
| `feature-map.yaml` | Features ↔ code paths ↔ routes/APIs ↔ tests ↔ rules; `depth` per feature |
| `journeys/J-xx-*.md` | Key end-to-end flows |
| `business-rules.yaml` | Rules with status, sources, confidence, lastVerified |
| `entities-states.yaml` | Entities, relationships, state machines |
| `app-map/app-map.yaml` | Pages/screens, navigation, per role (v2 crawl fills most of it) |
| `integrations.yaml` | External systems and failure modes |
| `environments.yaml` | Env URLs, account *references*, feature flags (no secrets) |
| `risk-hotspots.md` | Defect-prone / high-change / critical areas |
| `known-quirks.md` | Expected oddities (prevent false positives) |
| `discrepancies.md` | Open conflicts between sources |

## 2. Choose discovery mode per feature area

`domain.discovery.mode`:
- `docs-led` → `docs-led.md` (Scenario A: good requirement docs)
- `evidence-led` → `evidence-led.md` (Scenario B: no/poor docs)
- `auto` (default) → first build a **skeleton** (§3), then for each feature area estimate
  documentation coverage:
  - ≥ 1 requirement/spec doc that describes the feature's behaviour → `docs-led`
  - otherwise → `evidence-led`
  Record the chosen mode per feature in `feature-map.yaml` (`discoveryMode`).

**AI-DLC present (companion mode):** treat AI-DLC artifacts (reverse-engineering
outputs, requirements, stories, functional designs) as documentation → usually
`docs-led`. Use `integrations/aidlc/mapping.yaml` to locate them.

## 3. Skeleton (always, all features — cheap)

1. **Overview** from README, product docs, AI-DLC business overview if any.
2. **Feature list** from: top-level modules/folders, controllers/route groups, UI navigation
   definitions (router config, menu components), API spec tags, epics in tracker.
3. **Roles** from auth config: role enums, policy names, `[Authorize(Roles=...)]`,
   middleware guards, permission tables.
4. **Entities** from data model: ORM entities, migrations, schema files.
5. **Glossary** seeded from entity names, enum values, UI labels, frequent tracker terms.
6. Mark every feature `depth: skeleton`.

## 4. Depth (prioritised)

Deepen features selected by `domain.discovery.depth.deep`:
- `top-risk`: most bug-linked (tracker history), most churn (git log), hotspots named by users
- `top-usage`: if analytics/log data provided; otherwise ask the user to name top 5 journeys
Run the mode-specific procedure for each; set `depth: deep`.

## 5. Lazy deepening

When `domain.discovery.depth.lazy: true` and a work item's scope (context-loader §1)
includes a `depth: skeleton` feature, run the mode-specific procedure for **that feature only**
before stage 1.2. Results are raised as DCPs and reviewed at G1.

## 6. Every fact carries provenance

```yaml
- id: BR-012
  statement: "An employee cannot request more than 20 leave days in a single request."
  features: [F-leave-request]
  status: observed            # documented | observed | inferred | confirmed | disputed
  verified: false             # for documented facts: checked against code/tests/app?
  confidence: high            # high | medium | low (see corroboration.md)
  sources:
    - { type: test, ref: "tests/LeaveTests.cs#MaxDays", hash: "…" }
    - { type: error-message, ref: "src/Resources/Messages.resx#LeaveTooLong", hash: "…" }
  lastVerified: 2026-11-08
  tags: [limit]
```

## 7. Interview

Collect all uncertainties into **targeted interview** questions (`targeted-interview.md`)
in `PROJECT_DIR/questions.md`. Aim: ≤ 20 questions for the first round, highest-impact first.

## 8. Self-check (feeds G0)
- [ ] Every feature in `feature-map.yaml` has `depth` and `discoveryMode`
- [ ] Every rule/permission/state has `status`, `confidence`, ≥ 1 source
- [ ] No `observed`/`inferred` fact is phrased as an expectation without a status
- [ ] All conflicts are in `discrepancies.md` and have a question
- [ ] `environments.yaml` contains no secrets
- [ ] `domain-overview.md` has `domainVersion: 1.0.0-draft`
